## 解释时需要区分的因素

- C1、C2 的计划及估计成本相同。C1 有 shared read=31，C2 为 shared hit=1659；C2 比 C1 快不能直接归因于抑制顺序扫描，缓存状态和执行波动也有影响。
- D2 的估计总成本 8357.69 高于 D1 的 4091.51，且除访问全部 1636 个 heap blocks 外还处理大量索引项。尽管如此，本次 D2 的 22.959 ms 略低于 D1 的 24.116 ms；报告应保留这个实测结果，并说明单次运行不足以证明一种方法始终更快。
- C3 被抑制全部索引访问后，需要顺序读取全表并排除 188283 行，执行时间为 20.725 ms，高于 C 的两次位图扫描。
- D3 与 D1 均为顺序扫描，返回 188283 行，估计总成本同为 4091.51；本次耗时不同反映实际测量会变化。
