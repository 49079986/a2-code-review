### Q4.1 explanation draft

Connection 1 initially observed a Return as the latest event for VEH-0004. Its ordinary SELECT did not reserve the vehicle or prevent Connection 2 from inserting and committing a Reserve for member 2. Under READ COMMITTED, each statement uses a new snapshot, so the trigger invoked by Connection 1's later INSERT could see that committed reservation. The trigger rejected member 1's Collect, and COMMIT rolled back Connection 1's failed transaction; Connection 2's reservation remained committed. In business terms, the earlier availability answer had become stale. The simplified state model also treats the future-dated reservation as the latest event immediately, so a booking three days ahead prevents collection now. This is a stale availability check followed by a business-rule rejection, with no deadlock cycle.
