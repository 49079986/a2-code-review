先读整体，再逐行理解

代码第一条 SELECT 展示普通结果；第二条 EXPLAIN (ANALYZE, BUFFERS) 再真实执行一次查询并显示计划。两次执行不是同一计时样本。书写从 SELECT 开始，但逻辑先 FROM/JOIN、WHERE、GROUP BY，再做窗口和外层过滤；物理计划又可能用并行扫描、hash 连接等实现这些逻辑。

  1. L1SELECT * FROM V_BUSIEST_BAYS;

    读取 V_BUSIEST_BAYS 的全部结果列：车型类别、站名、取车次数。若上一行是 EXPLAIN，本行和上一行合起来是一条计划分析语句；否则直接显示视图结果。普通视图的定义会参与本次查询规划。

    Read the busiest-bays view, or explain that read when preceded by EXPLAIN.

  2. L2（空行）

    空行用于把相邻语义块分开，帮助区分输入、处理或独立语句；不执行 SQL、不提交事务，也不会重置配置。

    A visual separator only; it executes no statement and changes no transaction or setting.

  3. L3EXPLAIN (ANALYZE, BUFFERS)

    EXPLAIN 修饰紧接着的 SQL，输出物理计划；ANALYZE 会真正运行它并记录 actual time、rows 和 loops，BUFFERS 记录缓冲页访问。结果是计划文本而非普通结果表；cost 是优化器估计单位，不能当成毫秒，也不能将父子节点耗时简单相加。

    Execute the following query to collect its actual plan and buffer use; estimated cost is not milliseconds.

  4. L4SELECT * FROM V_BUSIEST_BAYS;

    读取 V_BUSIEST_BAYS 的全部结果列：车型类别、站名、取车次数。若上一行是 EXPLAIN，本行和上一行合起来是一条计划分析语句；否则直接显示视图结果。普通视图的定义会参与本次查询规划。

特殊函数、语法与符号

先区分函数、关键字、运算符和语句；下面的输入输出例子均是教学示例，未在网页连接数据库执行。

聚合函数

COUNT · 计数

COUNT(*) / COUNT(expression)

输入一组行，返回bigint计数；*计所有行，expression只计表达式非NULL行。

本作业中的作用
Q1.1统计每类车每站的Collect事件；Q2.2统计每个域名会员。
输入与输出示例
教学：amount为10、NULL、20时，COUNT(*)=3，COUNT(amount)=2。
边界与常见错误
空输入COUNT返回0。COUNT(DISTINCT vehicle_id)会变成不同车辆数，不能代替取车次数。
相关题目：Q1.1.1 · Q1.1.2 · Q2.1.3 · Q2.2.1 · Q2.2.2 · Q2.2.5
窗口函数

ROW_NUMBER · 窗口行号

ROW_NUMBER() OVER (PARTITION BY body_type ORDER BY collections DESC, station_id)

无普通参数；按窗口顺序返回从1开始的bigint，每个分区重新编号。

本作业中的作用
Q1.1在汇总结果上为每个body_type挑一个站点。
输入与输出示例
教学：Sedan/S1/5、Sedan/S2/5，加station_id排序后rn分别1、2。
边界与常见错误
不加稳定次序时并列胜者不确定；它不会像GROUP BY一样减少行数，要外层WHERE rn=1。
相关题目：Q1.1.1 · Q1.1.2 · Q2.1.2
DDL语句

VIEW · 普通视图

CREATE VIEW name AS query;

保存查询定义，读取时基于当次可见数据执行规划。

本作业中的作用
V_BUSIEST_BAYS、V_ACCOUNT_LIABILITY封装可重复调用的逻辑。
输入与输出示例
教学：底表费用从100变120后，再查普通视图看到符合快照的新总额120。
边界与常见错误
不会自动保存结果；创建成功不证明定义逻辑符合题目。同名CREATE通常报已存在。
相关题目：Q1.1.1 · Q1.1.2 · Q1.2 · Q1.3.2 · Q2.1.2
语句与选项

EXPLAIN / ANALYZE / BUFFERS · 观察真实工作

EXPLAIN (ANALYZE, BUFFERS) SELECT ...;

EXPLAIN只显示规划；加ANALYZE实际执行并给出测量；BUFFERS显示缓冲访问。

本作业中的作用
本作业比较计划成本、估计/实际行数、耗时与页访问。
输入与输出示例
教学：cost=0..10 rows=2，actual time=0.1..0.2 rows=6 loops=1，表示估2实6，成本不是0.2毫秒。
边界与常见错误
EXPLAIN ANALYZE会真的执行语句；用于修改语句时也会产生修改。BUFFERS父节点通常包含子节点，不重复求和。
相关题目：Q1.1.2 · Q1.3.2 · Q2.1.2 · Q2.1.3 · Q2.2.2 · Q2.2.5 · Q3.1.2 · Q3.2
执行计划字段

cost / rows / width / loops / time

cost=startup..total rows=estimate width=bytes; actual time=first..last rows=actual loops=n

cost为规划成本单位；width为估计平均输出字节；actual time单位ms，rows/time多循环时按每循环平均给出。

本作业中的作用
原生Q1.1扫描29769.5×2=59539条Collect；顶层估2实6。
输入与输出示例
教学：rows=100 loops=3表示平均每轮100行，总约300，不是总100。
边界与常见错误
父节点时间包含其子树部分工作，不能把所有层时间相加。并行worker与总墙钟时间需结合完整计划。
相关题目：Q1.1.2 · Q1.3.2 · Q3.1.2 · Q3.2
物理执行节点

Hash Join / Anti Join / Aggregate / Sort / WindowAgg

input scans → joins → aggregation → sorting/window

Hash Join按键建立哈希匹配；Anti Join保留无匹配；Aggregate把行变组；Sort排序；WindowAgg计算窗口。

本作业中的作用
Q1为事件补车型站点并排名；Q3反连接保留从未Collect的车。
输入与输出示例
教学：3事件连唯一车辆仍3行，按站计数可能成2组，窗口仍2行，外层rn=1才减少。
边界与常见错误
节点方向Right不改变目标语义；Batches/Sort Method等信息决定是否溢盘，不能凭cost猜。
相关题目：Q1.1.2 · Q2.2.2 · Q3.1.2

从要求推到结论

代码第一条 SELECT 展示普通结果；第二条 EXPLAIN (ANALYZE, BUFFERS) 再真实执行一次查询并显示计划。两次执行不是同一计时样本。书写从 SELECT 开始，但逻辑先 FROM/JOIN、WHERE、GROUP BY，再做窗口和外层过滤；物理计划又可能用并行扫描、hash 连接等实现这些逻辑。

原生计划的底层 Parallel Seq Scan 筛 Collect，经过 Hash Join 补属性，部分聚合再 Finalize GroupAggregate 汇成279组，Incremental Sort 与 WindowAgg 完成分区排名，最上面排序输出6行。读树先从最深缩进的输入向父节点追踪，不能把每层时间相加当作总时间。

原生计划 actual rows=29769.5、loops=2 意味着该节点每次循环的平均输出，合计59539条；并行节点的时间和行数要结合 loops 和 worker 信息读。顶层估计2行、实际6行是估计误差，并不是少显示4行。

检查理解

为什么结果只有6行，仍需要处理59539条 Collect？

展开参考答案

必须先知道每种类别、每站的取车总数，才能确定冠军。最终过滤压缩输出，却不会消除为计算冠军所需的底层工作。

再检查一个关键点

把所有计划节点的actual time相加，能得到Execution Time吗？

展开参考答案

不能。父节点已包含其子树的部分工作，并行/循环也影响读法；总计以计划末尾Execution Time为准。
