英文原题 · Original task

作业要求 PDF · a2-2026-v1.pdf · Q1.1 View A (1.5 marks)

The co-operative's planners want to know where each kind of vehicle is actually being picked up, so they can decide where to add parking bays.

(1) Create a view V_BUSIEST_BAYS that reports, for each body type, the single station at which vehicles of that body type have been collected the most times. The view should show the body type, the station name, and the number of collections, ordered from most collections to fewest. (1 mark) Hint: this is a "top item within each group" problem. Consider a window function such as RANK() or ROW_NUMBER() with a PARTITION BY clause, and use Common Table Expressions to build the query up in a semantically meaningful way.

合作社的规划人员希望知道，各类车实际最常在哪个站点被取走，以决定在哪里增加停车位。

（1）创建视图 V_BUSIEST_BAYS：对于每种车身类别（body type），报告该类别车辆取车次数最多的单个站点。视图应显示车身类别、站点名称和取车次数，并按取车次数从多到少排序。（1分）

06

先读整体，再逐行理解

先从 BOOKING_EVENTS 中找 Collect。一次取车是一条事件；同一辆车取走十次就贡献十次，而不是 COUNT(DISTINCT vehicle_id)。经 e.vehicle_id=v.vehicle_id 得到车辆，经 v.model_code=m.model_code 得到 body_type，经 v.station_id=s.station_id 得到站名。目标主键唯一，所以这些连接不会把一条事件随意放大。

  1. L1CREATE VIEW V_BUSIEST_BAYS AS

    CREATE VIEW 建立名为 V_BUSIEST_BAYS 的普通视图，AS 后面的 SELECT 是它保存的查询定义。普通视图不是结果快照，读取时由数据库规划并计算这条查询。

    CREATE VIEW names the ordinary view V_BUSIEST_BAYS; AS introduces its stored query definition. It stores a query rather than a snapshot of result rows.

  2. L2WITH collection_counts AS (

    WITH 定义只在当前查询内可见的 CTE collection_counts。括号内先解决“每种车型在每站取过几次车”，把计数和后面的排名分开；CTE 不等于永久表，也不保证一定物化。

    WITH introduces the query-local CTE collection_counts. It separates counting from ranking; a CTE is neither a permanent table nor necessarily materialized.

  3. L3 SELECT

    SELECT 开始声明 collection_counts 的输出列。它在代码中写在 FROM 前面，理解时却先确定 FROM/JOIN 的输入，再看 WHERE、GROUP BY，最后看输出列。

    Begin the count CTE projection; textual order differs from logical processing.

  4. L4 m.body_type,

    输出车型表 m 的 body_type，即 Sedan、SUV 等车身类别。这里末尾逗号表示输出列还没有写完；这不是按车辆逐一输出。

    Project the model body type; the comma continues the select list.

  5. L5 s.station_id,

    输出站点表 s 的唯一 station_id，以免两个同名站点混为一组；该编号也供后面的并列次数排序使用。

    Retain the unique station ID for grouping and deterministic ties.

  6. L6 s.station_name,

    输出站点的可读名称 station_name。它用于最终展示，但名称没有唯一约束，所以还需要 station_id 识别站点。

    Retain the display name without treating names as unique identifiers.

  7. L7 COUNT(*) AS collections

    COUNT(*) 数分组中的事件行，并把结果列命名为 collections。后面 WHERE 只保留 Collect，连接目标的主键又是唯一的，因此这里数的是取车事件次数，不是车辆数。

    COUNT(*) counts event rows in each group and names the column collections. The Collect filter and joins to unique keys make this a count of collections, not distinct vehicles.

  8. L8 FROM BOOKING_EVENTS e

    从事件日志 BOOKING_EVENTS 开始，给它别名 e。车可以多次被取用，所以不能只从 VEHICLES 数车辆来替代事件次数。

    Read BOOKING_EVENTS as e. A vehicle may be collected repeatedly, so counting fleet vehicles cannot replace counting events.

  9. L9 JOIN VEHICLES v

    把 VEHICLES 作为内连接的右侧输入，别名 v。需要从每条事件找到车辆记录，才能继续取得车型和站点；真正的匹配条件在下一行 ON。

    Join the vehicle table as v; the next ON clause specifies the match.

  10. L10 ON v.vehicle_id = e.vehicle_id

    用 v.vehicle_id = e.vehicle_id 将事件接到对应车辆。车辆主键唯一且事件外键指向它，因此合法事件不会因为这次连接而复制成多辆车。

    Match each event to its vehicle through the unique vehicle key.

  11. L11 JOIN MODELS m

    继续内连接 MODELS，别名 m。它描述车型规格而不是一辆实体车，下一行通过车型代码取得车辆对应的规格。

    Introduce the model-specification table as m.

  12. L12 ON m.model_code = v.model_code

    将车辆的 model_code 与 MODELS 主键 model_code 相等匹配，取得 body_type；不能误用 vehicle_id 连接车型。

    Match vehicle model_code to the model primary key.

  13. L13 JOIN STATIONS s

    继续内连接 STATIONS，别名 s，以取得车辆所记录站点的编号和名称。事件表没有独立的历史取车地点列。

    Introduce stations for the vehicle-recorded location.

  14. L14 ON s.station_id = v.station_id

    将 s.station_id 与 v.station_id 匹配，读出车辆当前记录的站点。此数据结构不能证明车辆历次取车时都在同一地点，应说明这个业务建模限制。

    Match the recorded vehicle station, without inventing event locations.

  15. L15 WHERE e.event_type = 'Collect'

    只保留事件类型等于字符串 Collect 的行；单引号表示字符串，e.event_type 是列。Reserve、Return 等其他事件不进入后续计数。

    Keep only rows whose event_type equals the string Collect. Single quotes delimit a string literal; other event types are excluded before counting.

  16. L16 GROUP BY

    GROUP BY 开始列出聚合分组键。输入先筛为 Collect，再按下面的车型和站点组合分组，每组计算一次 COUNT(*)。

    Begin grouping Collect events by body type and station.

  17. L17 m.body_type,

    作为分组键，m.body_type 使不同车身类别分别计数；同样车型类别的多种 model_code 可以进入同一个类别。

    Group different models by their shared body type.

  18. L18 s.station_id,

    作为分组键，s.station_id 区分每个真实站点，因此相同车身类别但站点不同的事件分开统计。

    Separate stations within each body type by station ID.

  19. L19 s.station_name

    将站名也列为分组键，与 SELECT 的非聚合输出保持一致。此处没有末尾逗号，表示分组键列表结束。

    Include the station name in the grouping and finish the key list.

  20. L20),

    右括号关闭 collection_counts 的查询体；逗号说明 WITH 还要定义下一个 CTE。此时中间结果每行代表一种车型在一个站点的取车次数。

    Close the count CTE and continue to the next CTE.

  21. L21ranked_stations AS (

    定义第二个 CTE ranked_stations，用来在每个 body_type 内给站点计数排名。它只在这条视图定义查询中有效，不是永久表。

    Name the second CTE that ranks station counts within each body type.

  22. L22 SELECT *,

    SELECT * 保留 collection_counts 已有各列；末尾逗号准备再加一个排名列。星号不会额外聚合，也不是只取第一行。

    Retain all count columns before adding a ranking column.

  23. L23 ROW_NUMBER() OVER (

    ROW_NUMBER() 为窗口中每行分配从 1 开始的整数，空括号表示无需函数参数；OVER 后括号定义分区和排序。它不会像 GROUP BY 那样合并行。

    Start a row-number window; OVER specifies partitions and ordering.

  24. L24 PARTITION BY body_type

    PARTITION BY body_type 让每种车型分别从 1 开始排名。如果省略这一行，就会把所有车型混在同一个总排名里。

    PARTITION BY body_type restarts numbering for each body type. Without it, all body types would compete in a single global ranking.

  25. L25 ORDER BY collections DESC, station_id

    每种车型内部按 collections 降序，次数最多的排前面；相同次数时 station_id 默认升序。这个额外规则使 ROW_NUMBER 恰好选出一个确定的站点，而 RANK 可能产生多个并列第一。

    Within each body type, sort counts descending and station_id ascending for ties. The extra key gives ROW_NUMBER one deterministic winner; RANK could retain tied winners.

  26. L26 ) AS rn

    关闭 OVER 的窗口定义，并把排名结果命名为 rn。rn 是这一层新增的列，下一层才能用 WHERE rn = 1 过滤，不能直接在同层 WHERE 中引用窗口结果。

    Close OVER and name the window output rn. An outer query can filter rn; the same SELECT level’s WHERE cannot directly filter its window result.

  27. L27 FROM collection_counts

    第二个 CTE 的输入是已经聚合的 collection_counts。窗口排名作用于“车型＋站点”的计数行，而不是直接给原始事件逐条排名。

    Rank the aggregated body-type/station count rows, rather than raw events.

  28. L28)

    结束 ranked_stations 的查询定义；下面的 SELECT 是整条 WITH 查询的最终输出。括号只划定语法范围，不是事务结束。

    Close ranked_stations. The following SELECT is the final WITH-query output; this parenthesis is a scope boundary, not a transaction boundary.

  29. L29SELECT body_type, station_name, collections

    最终只输出题目要求的 body_type、station_name 和 collections。station_id 与 rn 是实现排名所需的辅助列，不暴露为视图的结果列。

    Project only the required body type, station name and count. station_id and rn are internal ranking helpers, not final view columns.

  30. L30FROM ranked_stations

    从含有每组序号的 ranked_stations 读取。此时每一行仍代表一个车型与站点组合，但已经知道它在本车型中的排名。

    Read ranked_stations, where each body-type/station row now has its within-type rank.

  31. L31WHERE rn = 1

    每种车型仅保留 rn = 1，所以每个有符合条件取车记录的车型类别得到一个站点。它不是全表 LIMIT 1；没有 Collect 的类别不会被这条内连接查询凭空补出来。

    Keep one winning station per represented body type; absent categories are not synthesized.

  32. L32ORDER BY collections DESC, body_type;

    把六个获胜站点按取车次数从多到少排列；次数相同再按 body_type 排序。分号结束 CREATE VIEW 整条语句，后续查询该视图即可执行这个定义。

    Sort the six winners by count descending and then body type. The semicolon ends CREATE VIEW; subsequent reads use this definition.

特殊函数、语法与符号

先区分函数、关键字、运算符和语句；下面的输入输出例子均是教学示例，未在网页连接数据库执行。

聚合函数

COUNT · 计数

COUNT(*) / COUNT(expression)

输入一组行，返回bigint计数；*计所有行，expression只计表达式非NULL行。

本作业中的作用
Q1.1统计每类车每站的Collect事件；Q2.2统计每个域名会员。
输入与输出示例
教学：amount为10、NULL、20时，COUNT(*)=3，COUNT(amount)=2。
边界与常见错误
空输入COUNT返回0。COUNT(DISTINCT vehicle_id)会变成不同车辆数，不能代替取车次数。
相关题目：Q1.1.1 · Q1.1.2 · Q2.1.3 · Q2.2.1 · Q2.2.2 · Q2.2.5
窗口函数

ROW_NUMBER · 窗口行号

ROW_NUMBER() OVER (PARTITION BY body_type ORDER BY collections DESC, station_id)

无普通参数；按窗口顺序返回从1开始的bigint，每个分区重新编号。

本作业中的作用
Q1.1在汇总结果上为每个body_type挑一个站点。
输入与输出示例
教学：Sedan/S1/5、Sedan/S2/5，加station_id排序后rn分别1、2。
边界与常见错误
不加稳定次序时并列胜者不确定；它不会像GROUP BY一样减少行数，要外层WHERE rn=1。
相关题目：Q1.1.1 · Q1.1.2 · Q2.1.2
窗口函数

RANK · 允许并列的排名

RANK() OVER (PARTITION BY ... ORDER BY ...)

相同窗口排序键得到同排名，下一排名跳号。

本作业中的作用
原题提示RANK或ROW_NUMBER，当前答案选ROW_NUMBER以满足single station。
输入与输出示例
教学：次数5、5、3且只按次数排序，RANK=1、1、3，ROW_NUMBER=1、2、3。
边界与常见错误
RANK后取rank=1可能返回两个站点；若排序又加唯一ID，则不再并列。
相关题目：Q1.1.1
关键字/查询结构

WITH / CTE · 给中间查询命名

WITH counts AS (SELECT ...) SELECT ... FROM counts;

命名结果仅对当前SQL可见，便于把计算分阶段。不是创建永久表，也不必然物化。

本作业中的作用
Q1把计数与排名分开；Q4给最新事件中间结果命名。
输入与输出示例
教学：WITH x AS (SELECT 2 AS n) SELECT n+1 FROM x; 返回3。
边界与常见错误
多个CTE用逗号隔开；CTE结束后的外层SELECT仍属于同一条语句。优化器可内联，不要用书写结构猜扫描次数。
相关题目：Q1.1.1 · Q1.2 · Q1.3.1 · Q4.1.1
关键字

JOIN / ON / 别名 · 补齐关联属性

FROM BOOKING_EVENTS e JOIN VEHICLES v ON v.vehicle_id=e.vehicle_id

内连接保留符合ON的行对；e/v是查询局部别名，点号取对应表列。

本作业中的作用
事件没有body_type和station_name，必须经车辆到车型和站点。
输入与输出示例
教学：事件(V1,Collect)与车辆(V1,MD1,S1)连接后才知道车型和站点ID。
边界与常见错误
目标主键唯一避免此连接成倍放大事件。漏写连接条件会形成笛卡尔积；同名列要写别名前缀。
相关题目：Q1.1.1 · Q1.2 · Q3.1.1
关键字

GROUP BY / WHERE / HAVING · 逻辑阶段

FROM/JOIN → WHERE → GROUP BY/aggregate → HAVING → window → SELECT → ORDER BY → LIMIT

WHERE先筛输入行；GROUP BY把相同键行合组；HAVING筛聚合组；窗口在分组后处理已有行。

本作业中的作用
先筛Collect再数每站次数；窗口rn须外层过滤。
输入与输出示例
教学：筛掉Return后3条Collect归一组COUNT=3，不能把所有事件先数完再显示Collect。
边界与常见错误
这是逻辑解释顺序，不是强制物理执行顺序。HAVING未在原答案使用，列出是帮助理解阶段差异。
相关题目：Q1.1.1 · Q1.2 · Q2.2.1
关键字

ORDER BY / DESC / LIMIT / AS

ORDER BY collections DESC, station_id ASC LIMIT 1

排序键从左到右比较；默认ASC，DESC降序；LIMIT限制输出；AS给对象/列起名。

本作业中的作用
每类冠军、账户top10、最新事件、同值稳定次序。
输入与输出示例
教学：次数5/ID2与5/ID1，降序次数相同再ID升序，ID1先。
边界与常见错误
LIMIT无确定排序可能不稳定；视图或物化关系调用方需要保证显示顺序时显式ORDER BY。
相关题目：Q1.1.1 · Q1.2 · Q1.3.3 · Q4.1.1
DDL语句

从要求推到结论

先从 BOOKING_EVENTS 中找 Collect。一次取车是一条事件；同一辆车取走十次就贡献十次，而不是 COUNT(DISTINCT vehicle_id)。经 e.vehicle_id=v.vehicle_id 得到车辆，经 v.model_code=m.model_code 得到 body_type，经 v.station_id=s.station_id 得到站名。目标主键唯一，所以这些连接不会把一条事件随意放大。

第一层 CTE 按 body_type、station_id、station_name 分组得到 collections。第二层对每个 body_type 单独按次数降序编号；station_id 打破并列。外层 WHERE rn=1 挑冠军，再对各类别冠军排序。窗口结果在 WHERE 之后产生，因此需要外层过滤；直接在同层 WHERE 写 ROW_NUMBER() 不成立。
