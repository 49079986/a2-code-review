前置知识与数据库背景

一个连接是一个独立服务器会话，用pg_backend_pid辨认。BEGIN到COMMIT/ROLLBACK是一笔事务；未提交写入通常不对其他会话可见。默认READ COMMITTED每条命令取得新快照。行锁协调冲突写入；快照回答可见性，不能代替锁。

06

先读整体，再逐行理解

INSERT执行前BI_COLLECT触发器读取该车最新事件。会话2已提交，当前语句可看到Reserve；最新事件按event_time排，三天后的Reserve排在现在的Collect前。last_member=2与NEW.member_id=1不同，RAISE EXCEPTION拒绝插入。

  1. L1-- Connection 1: use the original open transaction after Connection 2 commits.

    连接1继续原先未结束事务，并确保连接2已提交 Reserve。这是同一事务中的后续语句，不是新开一个事务重试。

    Continue the original session 1 transaction after session 2 commits.

  2. L2-- Do not reconnect or start a new transaction before running these statements.

    注释禁止重新连接或再开新事务，因为那会破坏第(1)步旧检查与第(3)步新动作之间的实验关系。

    Preserve the original connection and transaction.

  3. L3\set ON_ERROR_STOP off

    psql 的 ON_ERROR_STOP 设为 off，让脚本遇预期触发器错误后继续运行 COMMIT 和核对 SELECT。它只改变客户端是否停脚本，不能撤销服务器错误或修复失败事务。

    Allow psql to continue after an error without repairing the failed transaction.

  4. L4（空行）

    空行用于把相邻语义块分开，帮助区分输入、处理或独立语句；不执行 SQL、不提交事务，也不会重置配置。

    A visual separator only; it executes no statement and changes no transaction or setting.

  5. L5-- Attempt to collect the same vehicle for a different member.

    注释说明 member_id 1 尝试收取同一辆车，与预约的 member_id 2 不同。该 INSERT 会触发已有 BI_COLLECT 规则检查。

    Attempt collection for a member different from the reserver.

  6. L6INSERT INTO BOOKING_EVENTS

    开始向事件日志插入 Collect；真正能否插入由数据约束与 BI_COLLECT 触发器共同决定，不是客户端直接绕过检查。

    Begin the Collect insert subject to the supplied trigger.

  7. L7 (member_id, vehicle_id, event_type, event_time, amount)

    目标列依次为会员、车辆、类型、时间、金额；缺省 event_id 由序列提供，即使之后失败也可能留下序列号间隙。

    Declare inserted columns; sequence allocation may survive a failed insert.

  8. L8VALUES

    VALUES 表明下面直接提供一行常量与函数表达式，不从其他表批量选择。

    Start one literal insert row.

  9. L9 (1, 'VEH-0004', 'Collect', NOW(), NULL);

    会员1在 VEH-0004 上尝试 Collect，时间用本连接事务起点 NOW()，金额为 NULL。READ COMMITTED 的新语句可见性与 NOW() 的事务固定时间是不同概念；触发器可看到连接2已提交的未来 Reserve。

    Attempt the Collect row using session 1 transaction time; the trigger can see the committed reservation.

  10. L10（空行）

    空行用于把相邻语义块分开，帮助区分输入、处理或独立语句；不执行 SQL、不提交事务，也不会重置配置。

    A visual separator only; it executes no statement and changes no transaction or setting.

  11. L11-- After the expected trigger error, COMMIT ends the failed transaction as ROLLBACK.

    注释说明预期触发器异常会令连接1事务失败；本脚本没有使用第(1)步建立的保存点恢复，因此后面的 COMMIT 实际结束为 ROLLBACK。具体输出要以该版本日志为证。

    The expected trigger error leaves this transaction failed without savepoint recovery.

  12. L12COMMIT;

    尝试 COMMIT。若上一条 Collect 因触发器异常失败，且未 ROLLBACK TO 保存点，PostgreSQL 会回滚失败事务并报告 ROLLBACK，不能把它解释为成功提交 Collect。

    End the failed transaction by rollback despite the COMMIT command.

  13. L13（空行）

    空行用于把相邻语义块分开，帮助区分输入、处理或独立语句；不执行 SQL、不提交事务，也不会重置配置。

    A visual separator only; it executes no statement and changes no transaction or setting.

  14. L14-- Check the latest recorded events after the transaction has ended.

    事务结束后再查询最新事件，核实 Reserve 是否保留以及失败 Collect 是否不存在。命令文本本身不是插入成功的证据。

    Verify recorded events after the failed transaction ends.

  15. L15SELECT event_id, member_id, vehicle_id, event_type, event_time, amount

    选择事件ID、会员、车辆、类型、时间和金额，使读者能区分预约人、取车人、事件种类与先后关系。

    Project event identity, actor, type, time and amount.

  16. L16FROM BOOKING_EVENTS

    直接读取已提交的 BOOKING_EVENTS。先前失败事务已经结束，新的普通语句可继续运行，不会仍处于 aborted 状态。

    Read committed event rows after ending the failed transaction.

  17. L17WHERE vehicle_id = 'VEH-0004'

    只核对本次实验车 VEH-0004，不要用旧版 VEH-0001 的结果替代此版本证据。

    Verify the current experiment vehicle VEH-0004.

  18. L18ORDER BY event_time DESC, event_id DESC

    按时间与事件ID降序排列，先看最新状态。未来3天的 Reserve 会排在“现在”的事件之前，这是简化业务模型的关键。

    Sort newest event first; future reservations sort ahead of present events.

  19. L19LIMIT 3;

    最多显示最近三条事件并结束 SELECT。LIMIT 3 只是展示窗口，不能据此断言该车全部历史只有三条。

    Show at most three recent events, not the complete history.

NULL / IS NULL / 三值逻辑

x IS NULL; x IS NOT NULL

NULL表示缺失或未知；普通比较产生unknown，不等同于空字符串或0。

本作业中的作用

事务控制语句

BEGIN / COMMIT / ROLLBACK / SAVEPOINT

BEGIN; SAVEPOINT s; ... COMMIT; / ROLLBACK TO s;

BEGIN开启事务；COMMIT成功则持久化；ROLLBACK撤销；SAVEPOINT标记局部可恢复点。

本作业中的作用
Q4保持两事务重叠，异常后COMMIT实际返回ROLLBACK。
输入与输出示例
教学：第一UPDATE成功、第二死锁，受害事务第一次更新也被撤销。
边界与常见错误
SAVEPOINT本身不自动恢复；需ROLLBACK TO。函数体BEGIN...END是语言代码块，不是独立事务。
相关题目：Q4.1.1 · Q4.1.3 · Q4.2.1
隔离级别与可见性

READ COMMITTED / snapshot · 读已提交快照

SHOW transaction_isolation;

默认READ COMMITTED每条命令看到该命令快照允许的已提交内容和自身可见修改。

本作业中的作用
T1先见Return，T2提交后T1后续Collect触发器见Reserve。
输入与输出示例
教学：两条SELECT之间别人提交更新，第二条可以读到不同值。
边界与常见错误
事务打开不固定首次快照；快照不是预留锁。普通SELECT仍取得兼容表锁，原题“无锁”是简化。

触发器与PL/pgSQL

BI_COLLECT / NEW / RAISE EXCEPTION

BEFORE INSERT ... FOR EACH ROW EXECUTE FUNCTION UDF_BI_COLLECT();

每个插入候选行之前调用函数；NEW是拟插入记录；RETURN NEW允许继续，RAISE EXCEPTION拒绝并抛错。

本作业中的作用
Collect时读该车按时间/ID最新事件，检查Incident、Collect或其他会员Reserve。
输入与输出示例
教学：last_type=Reserve且last_member=2、NEW.member_id=1时抛Vehicle ... reserved。
边界与常见错误
Reserve本身不进入Collect检查；最新未来事件也会当当前状态。NEW还不是已提交表行；触发器没有独立事务。

INSERT SELECT把查询结果作为新行；VALUES写字面行；RETURNING输出本语句改变的行字段。

psql提示符与命令状态

主报告p39与Q4.1_VEH0004_collect_result.png保留原生错误和最后事件。根SQL使用\set ON_ERROR_STOP off，使psql在预期错误后仍继续执行COMMIT与核验查询；它不使数据库忽略错误或自动提交失败插入。

记录轮次时间线 · VEH-0004 · 默认 READ COMMITTED
步骤T1 / LEFTT2 / RIGHT含义
1BEGIN；最新Return，可用—T1第一次检查只读，不预留
2保持事务打开BEGIN；同车仍ReturnT1未提交并不阻止T2检查
3仍打开写member2未来Reserve；COMMIT新预约对后续命令可见
