前置知识与数据库背景

一个连接是一个独立服务器会话，用pg_backend_pid辨认。BEGIN到COMMIT/ROLLBACK是一笔事务；未提交写入通常不对其他会话可见。默认READ COMMITTED每条命令取得新快照。行锁协调冲突写入；快照回答可见性，不能代替锁。

先读整体，再逐行理解

文件先连接assignment2并显示PID。psql的\connect/\c是客户端命令，不是SQL；重新连接会替换当前会话，所以只能在第2个窗口运行，不能误关仍打开的连接1。

  1. L1-- Connection 2: run this file while Connection 1 remains in its open transaction.

    连接2运行说明：连接1应仍处于开放事务；本文件在独立连接执行，不能重用连接1，否则会破坏交错顺序。

    Run this file in independent session 2 while session 1 stays open.

  2. L2\set ECHO all

    psql 客户端回显输入命令，便于输出截图证明实际执行顺序；它不是 SQL，也不控制事务隔离。

    Echo psql input commands.

  3. L3\connect assignment2

    psql 的 \connect assignment2 重新建立到 assignment2 的数据库连接。必须只在连接2执行，重新连接连接1会丢掉原事务；GUI SQL 编辑器通常不识别这个元命令。

    Reconnect session 2 to assignment2 using a psql meta-command.

  4. L4\pset pager off

    关闭当前 psql 会话的输出分页器，不修改数据库数据。

    Disable the psql output pager in session 2.

  5. L5\timing on

    开启客户端语句计时，帮助记录每步耗时；不能据此把等待、网络与计划节点时间当作同一指标。

    Enable client statement timing.

  6. L6（空行）

    空行用于把相邻语义块分开，帮助区分输入、处理或独立语句；不执行 SQL、不提交事务，也不会重置配置。

    A visual separator only; it executes no statement and changes no transaction or setting.

  7. L7-- Identify the independent connection used for the reservation.

    注释标记连接2身份查询；它要与连接1同库但 PID 不同。

    Record the independent reservation session identity.

  8. L8SELECT pg_backend_pid() AS session_pid,

    返回连接2后台 PID，命名为 session_pid。与连接1输出对比，后台 PID 应不同；PID 本身不是事务编号。

    Return session 2 backend PID, not its transaction ID.

  9. L9 current_database() AS database_name;

    返回当前数据库名，核对为 assignment2，保证连接2预订写入和连接1读取属于同一个数据库。

    Return the connected database name.

  10. L10（空行）

    空行用于把相邻语义块分开，帮助区分输入、处理或独立语句；不执行 SQL、不提交事务，也不会重置配置。

    开始连接2自己的事务；它与连接1的事务相互独立，连接2的 COMMIT 只提交连接2的写入。

    Begin the independent session 2 transaction.

  12. L12SHOW transaction_isolation;

    显示连接2隔离级别，核对实验条件为 READ COMMITTED。SHOW 读取设置，不会把错误级别自动改正。

  14. L14-- Check the same vehicle selected by Connection 1.

    注释说明要检查与连接1相同的车辆；检查别的车辆无法展示同一对象被另一个事务改变。

    Check the same selected vehicle.

  15. L15SELECT *

    外层 SELECT * 输出内层最新事件的五列，供证据展示；星号作用于子查询结果，不是读取 MEMBERS 的全部数据。

    Project all columns of the latest-event subquery.

  16. L16FROM (

    FROM ( 开始派生表子查询。它先按这辆车的所有历史事件排序并取最新，再由外层判断 Return。

    Start the derived-table query that selects the latest event.

  17. L17 SELECT vehicle_id, event_id, member_id, event_type, event_time

    选择车辆编号、事件编号、会员、类型和时间。字段顺序决定外层星号的显示顺序。

    从事件日志读取车辆状态历史。这里的普通 SELECT 不会为随后 INSERT 预先预留车辆。

    仅查看 VEH-0004 的事件，必须与连接1选出的编号一致；字符串字面值使用单引号。

    按事件时间降序，同时间再按 event_id 降序，使 LIMIT 1 选到稳定的最新记录。不能先过滤 Return 再排序。

    内层只取最新一条事件；该车若没有历史，内层零行，外层自然也没有可用结果。

    检查已经选出的最新类型是否 Return，并结束 SELECT。此检查成功只代表该语句快照下可用，不等于预约已写入。

    A visual separator only; it executes no statement and changes no transaction or setting.

  25. L25-- Reserve the vehicle for member 2 three days in the future.

    注释说明下一条把同一辆车预约给 member_id 2，预约时间为当前事务起点后3天。该教学模型将未来 Reserve 直接影响最新状态。

    Label the three-day-future reservation for member 2.

  26. L26INSERT INTO BOOKING_EVENTS

    向 BOOKING_EVENTS 插入 Reserve 事件；这条写入在 COMMIT 前只对本事务可见，不能仅看 INSERT 成功就认定已提交。

    Begin inserting the reservation event.

  27. L27 (member_id, vehicle_id, event_type, event_time, amount)

    指定目标五列：会员、车辆、类型、时间、金额；省略 event_id，让默认序列取号。VALUES 的五值必须按此顺序对应。

    Declare the inserted event columns in positional order.

  28. L28VALUES

    VALUES 开始常量行数据，与 Q1.3 的 INSERT…SELECT 不同，此处直接给出一个五值元组。

    Start a literal VALUES row.

  29. L29 (2, 'VEH-0004', 'Reserve', NOW() + INTERVAL '3 days', NULL)

    写入会员2、VEH-0004、Reserve、NOW()+INTERVAL '3 days' 和 NULL 金额。NOW() 返回当前事务开始时间，区间加法得到3天后；NULL 是缺值，不能写成字符串 'NULL'。

    Supply the reservation values; NOW is transaction start time and NULL is a null value.

  30. L30RETURNING event_id, member_id, vehicle_id, event_type, event_time;

    RETURNING 返回本条 INSERT 实际写入的事件编号及其他列，可核对序列号与时间。它不是独立 SELECT，也不自动提交。

    Return the inserted row identity and values without committing.

  31. L31（空行）

    空行用于把相邻语义块分开，帮助区分输入、处理或独立语句；不执行 SQL、不提交事务，也不会重置配置。

    A visual separator only; it executes no statement and changes no transaction or setting.

  32. L32COMMIT;

    提交连接2事务，使 Reserve 成为已提交事件。连接1在 READ COMMITTED 下后续新语句可看到它，但连接1早先的结果不会自动更新。

    Commit the reservation for visibility to subsequent statements in session 1.

  33. L33（空行）

    空行用于把相邻语义块分开，帮助区分输入、处理或独立语句；不执行 SQL、不提交事务，也不会重置配置。

    A visual separator only; it executes no statement and changes no transaction or setting.

  34. L34-- Return to Connection 1 only after this COMMIT succeeds.

    只有连接2 COMMIT 成功后才返回连接1尝试 Collect；否则可能演示不同的可见性顺序，不能与本题记录混用。

    Return to session 1 only after this commit succeeds.

日期时间函数

NOW · 事务起点时间

NOW() → timestamp with time zone

无参数，返回当前事务开始时间，事务内多次调用保持稳定。

本作业中的作用
Q4记录现在的Collect，以及NOW()+INTERVAL '3 days'的Reserve。
输入与输出示例
教学：同一事务等10秒再NOW()仍是事务开始时间；加3 days是三天后的时间值。
边界与常见错误
event_time为timestamp without time zone，赋值时按会话时区转换，不能忽略环境。想读墙钟是另一函数clock_timestamp，原代码未使用。

信息函数

pg_backend_pid / current_database · 会话身份

pg_backend_pid() → integer; current_database() → name

前者返回当前后端进程编号，后者返回当前连接数据库名，均无参数。

本作业中的作用
Q4确认两个窗口是否独立、是否连接assignment2。
输入与输出示例
教学：窗口A PID8668，B40916，才能对应本轮左右窗口。
边界与常见错误
PID随连接重建会变，不能把本轮数字写死为事务逻辑；同一窗口重连会失去原事务。

命令/配置参数

SET / SHOW / enable_* · 会话配置

SET enable_seqscan = off; SHOW transaction_isolation;

SET改变当前连接后续配置，SHOW读取。enable_indexscan/indexonlyscan/bitmapscan/seqscan是不同开关。

本作业中的作用
Q3.2三种设置组最后全部恢复on；Q4 SHOW确认默认隔离。
输入与输出示例

边界与常见错误
off通常是抑制而非绝对无法使用；同文件需在同会话运行。配置不是SQL函数，也不修改表数据。

类型及运算

TIMESTAMP / INTERVAL / 半开区间

TIMESTAMP '2026-03-01'; NOW()+INTERVAL '3 days'

TIMESTAMP文字解析时间值；INTERVAL是时间长度；>=下界且<下一周期起点表示完整周期。

本作业中的作用

输入与输出示例
教学：[3月1日00:00,4月1日00:00)包含3月31日深夜。
边界与常见错误
event_time无时区，NOW有时区，赋值受会话TimeZone影响。日期文字不含时间时为00:00。

隔离级别与可见性

READ COMMITTED / snapshot · 读已提交快照

SHOW transaction_isolation;

默认READ COMMITTED每条命令看到该命令快照允许的已提交内容和自身可见修改。

本作业中的作用
T1先见Return，T2提交后T1后续Collect触发器见Reserve。
输入与输出示例
教学：两条SELECT之间别人提交更新，第二条可以读到不同值。
边界与常见错误
事务打开不固定首次快照；快照不是预留锁。普通SELECT仍取得兼容表锁，原题“无锁”是简化。

触发器与PL/pgSQL

BI_COLLECT / NEW / RAISE EXCEPTION

BEFORE INSERT ... FOR EACH ROW EXECUTE FUNCTION UDF_BI_COLLECT();

每个插入候选行之前调用函数；NEW是拟插入记录；RETURN NEW允许继续，RAISE EXCEPTION拒绝并抛错。

本作业中的作用
Collect时读该车按时间/ID最新事件，检查Incident、Collect或其他会员Reserve。
输入与输出示例
教学：last_type=Reserve且last_member=2、NEW.member_id=1时抛Vehicle ... reserved。
边界与常见错误
Reserve本身不进入Collect检查；最新未来事件也会当当前状态。NEW还不是已提交表行；触发器没有独立事务。

DML语句

INSERT ... SELECT / VALUES / UPDATE ... RETURNING

INSERT INTO t(cols) SELECT ...; UPDATE ... RETURNING vehicle_id,odometer;

INSERT SELECT把查询结果作为新行；VALUES写字面行；RETURNING输出本语句改变的行字段。

本作业中的作用
Q1.3选最大有赞助会员插入；Q4显示Reserve/里程修改值。
输入与输出示例
教学：149100+10 RETURNING149110，但BEGIN未提交时他人尚不能视为已提交。
边界与常见错误
UPDATE没WHERE可能改全表；RETURNING成功不是COMMIT成功。INSERT列顺序必须与SELECT/VALUES一一对应。

客户端显示

psql提示符与命令状态

assignment2=# / assignment2=*# / assignment2=!#

典型提示符中数据库名标识连接；*表示事务内，!表示事务失败；#常指当前角色具有超级用户权限，非所有环境都相同。

本作业中的作用
Q4用事务状态辨认未提交或失败；COMMIT后看实际返回COMMIT还是ROLLBACK。
输入与输出示例
教学：UPDATE 1只说修改一行，INSERT 0 1表示插入一行；它们不代表事务已提交。没有新提示符可能表示语句仍在等待。
边界与常见错误
括号/短横线等提示符可能表示输入尚未结束；仅凭等待画面不能证明死锁，需互相等待与错误证据。

从要求推到结论

文件先连接assignment2并显示PID。psql的\connect/\c是客户端命令，不是SQL；重新连接会替换当前会话，所以只能在第2个窗口运行，不能误关仍打开的连接1。

子查询先ORDER BY event_time DESC,event_id DESC LIMIT1，再外层检查Return。随后给member2插入Reserve，用NOW()+INTERVAL '3 days'表示事务起点时间加三天，RETURNING显示实际插入字段，COMMIT使其他事务的新语句可见。

NOW()在同一事务内稳定，不是每次调用都重新读墙钟。Reserve不会触发Collect拒绝分支，记录未来时间也没有表达预约结束区间；该简化模型把最新事件当当前状态。
