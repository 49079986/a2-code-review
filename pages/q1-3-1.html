06

先读整体，再逐行理解

CREATE MATERIALIZED VIEW ... AS 后复制整个账户责任查询。创建时执行查询并保存当时结果，因此当前保存的是10行冠军账户，不是24000个会员的完整中间映射。

  1. L1CREATE MATERIALIZED VIEW MV_ACCOUNT_LIABILITY AS

    CREATE MATERIALIZED VIEW 把同一个递归查询的当前结果实际存成 MV_ACCOUNT_LIABILITY。与普通视图不同，后续底层表变化不会自动更新这份结果，需要 REFRESH。

    CREATE MATERIALIZED VIEW stores the current recursive-query result as MV_ACCOUNT_LIABILITY. Unlike an ordinary view, it does not automatically reflect later base-table changes and requires REFRESH.

  2. L2WITH RECURSIVE account_tree AS (

    WITH RECURSIVE 允许 account_tree 在后半段引用自己的当前递归结果。这里从无赞助人的根账号往下找孩子，把每个成员映射到最终付款账号。

    WITH RECURSIVE lets account_tree refer to its current recursive rows. The traversal starts at unsponsored roots and propagates the ultimate payer down to descendants.

  3. L3 SELECT member_id, member_id AS account_id

    基础层把无赞助根账户的 member_id 同时输出为当前成员 member_id 和最终付款 account_id。教学例：根成员1产生 (1,1)，其后代也继续携带根 account_id 1；这不是一条收费记录。

    Seed each root as its own account; illustrative root 1 yields mapping (1,1).

  4. L4 FROM MEMBERS

    基础层从 MEMBERS 成员表读取，尚未访问收费日志。先建立成员到根的对应关系，再连接收费，能清楚区分层级关系与金额汇总。

    Read MEMBERS for the seed, before joining any charges. This separates hierarchy resolution from monetary aggregation.

  5. L5 WHERE sponsor_id IS NULL

    sponsor_id 为 NULL 的成员没有上级，需要自己付款，因此是根节点。判断 NULL 必须用 IS NULL，写 = NULL 不会得到期望的真值。

    Members with sponsor_id IS NULL are self-paying roots. IS NULL is required because ordinary equality with NULL does not test for nullness.

  6. L6（空行）

    空行用于把相邻语义块分开，帮助区分输入、处理或独立语句；不执行 SQL、不提交事务，也不会重置配置。

    A visual separator only; it executes no statement and changes no transaction or setting.

  7. L7 UNION ALL

    UNION ALL 合并基础层和后面一轮轮找出的孩子，不做去重。对给定的无环、每人至多一个 sponsor 的层级，每个成员只有一条根路径；这段代码本身不是通用的环检测器。

    UNION ALL appends recursive descendants without deduplication. In the supplied acyclic single-sponsor hierarchy, each member has one root path; this query is not a general cycle detector.

  8. L8（空行）

    空行用于把相邻语义块分开，帮助区分输入、处理或独立语句；不执行 SQL、不提交事务，也不会重置配置。

    A visual separator only; it executes no statement and changes no transaction or setting.

  9. L9 SELECT child.member_id, parent.account_id

    每次输出孩子自己的 member_id，但 account_id 仍复制父行携带的根账号。不能在此改成 parent.member_id，否则深层成员会被错误归到直接父母。

    Emit the child’s own member_id but retain the parent row’s ultimate account_id. Using parent.member_id instead would incorrectly bill deeper descendants to an intermediate sponsor.

  10. L10 FROM MEMBERS child

    把成员表中的候选孩子命名为 child。它们可能属于任意一层；是否接上当前递归结果，由下一行的连接条件决定。

    Read candidate child members from MEMBERS. The next join decides which ones descend from the current recursive frontier.

  11. L11 JOIN account_tree parent

    连接当前递归工作表 account_tree，并取别名 parent。每轮用上轮已知成员寻找直接被其赞助的孩子，root account_id 会沿整条链传下去。

    Join recursive working rows as parent to discover sponsored children.

  12. L12 ON child.sponsor_id = parent.member_id

    child.sponsor_id = parent.member_id 说明 child 由当前 parent 赞助。输出时携带 parent.account_id，而不是改成直接赞助人的编号，才能支持多层链。

    Follow the child-to-sponsor link while retaining the ultimate root account.

  13. L13)

    关闭递归 CTE 的定义。给定无环且每人至多一个 sponsor、所有链能到达根的结构时，每名成员会映射到一个最终账户；只有环而没有根的成员不会被此根向下遍历收录。递归本身不负责累加金额。

    Close the recursive definition; rootless cycles would not be reached by this traversal.

  14. L14SELECT

    开始最终 SELECT 的输出列列表。输入是已经建立的“成员 → 最终付款账户”映射，再接上账户姓名和收费事件。

    Begin the final projection over member-to-root mappings and charges.

  15. L15 root.member_id,

    输出根账户的 member_id；root 是后面 MEMBERS 的别名，不是 SQL 保留字。使用编号区别同名会员。

    Project the ultimate payer ID from the root member alias.

  16. L16 root.member_name,

    输出根账户的 member_name，方便人类识别付款人。不能把产生费用的子成员姓名误当作最终付款人姓名。

    Project the ultimate payer name, rather than the charged child name.

  17. L17 SUM(e.amount) AS total_amount

    SUM(e.amount) 把同一根账号下的有效收费相加，结果列叫 total_amount。SUM 会忽略 NULL；下面仍显式限定 Return 和 Incident 来表达业务含义。

    Sum charge amounts for each root as total_amount. SUM ignores NULL, while the explicit event-type filter states which events are charges.

  18. L18FROM account_tree t

    给 account_tree 结果别名 t。t.member_id 表示收费成员，t.account_id 表示该成员最终归属的付款账号。

    Read account_tree as t: t.member_id is the charged member and t.account_id is the ultimately liable account.

  19. L19JOIN MEMBERS root

    将映射结果连接回 MEMBERS，别名 root，用来读取最终付款根账户的资料。一个根账户可以对应很多被赞助成员。

    Join MEMBERS as root to obtain payer details.

  20. L20 ON root.member_id = t.account_id

    用 root.member_id = t.account_id 匹配映射中保存的根编号。t.member_id 是产生费用的人，t.account_id 才是承担费用的人。

    Match the root member to the account_id carried by each mapping.

  21. L21JOIN BOOKING_EVENTS e

    连接 BOOKING_EVENTS，别名 e，为映射中的每个成员取出实际事件与金额。不能直接只连接根账户自己的事件，否则会漏掉后代费用。

    Join each mapped member to event charges, including descendant charges.

  22. L22 ON e.member_id = t.member_id

    以 e.member_id = t.member_id 将费用接到实际产生该费用的成员，再按 t.account_id 汇入根。给定无环单赞助关系下，每个成员只映射到一个根。

    Attach an event to its charged member before aggregating at the root.

  23. L23WHERE e.event_type IN ('Return', 'Incident')

    只保留 Return 车费和 Incident 损坏收费。Reserve、Collect、Cancel 不属于本题费用事件，即使它们与同一成员有关也不应计入收费总额。

    Keep Return fares and Incident damage charges, excluding Reserve, Collect and Cancel from the monetary totals.

  24. L24 AND e.event_time >= TIMESTAMP '2026-01-01'

    使用带类型的 TIMESTAMP 字面量，从 2026-01-01 零点起包含记录。>= 保留恰好在年初零点发生的收费。

    Use a typed TIMESTAMP lower bound and include records at or after midnight on 1 January 2026.

  25. L25 AND e.event_time < TIMESTAMP '2026-07-01'

    排除 2026-07-01 零点及之后，因而包含 6 月 30 日的全部时间。这种半开区间不会像 <= 2026-06-30 零点那样漏掉最后一天后续事件。

    Exclude midnight on 1 July and later, thereby including all of 30 June. The half-open interval avoids truncating the final day at its midnight.

  26. L26GROUP BY root.member_id, root.member_name

    按最终根账号分组，同一个根名下的自己、子账号及更深层成员的费用合成一行。member_id 是主键，也避免把同名但不同 ID 的人合并。

    Group charges by the ultimate root account, including its own and all descendants’ charges. The identifier keeps distinct people with equal names separate.

  27. L27ORDER BY total_amount DESC, root.member_id

    先按总金额降序，金额相同再按根 member_id 升序。这个稳定的次排序让恰好前十名在并列边界时仍有确定选择。

    Sort total liability descending, then member_id ascending to make selection deterministic at a tied top-ten boundary.

  28. L28LIMIT 10;

    LIMIT 10 在排序后只保留最高的十个根账户。不能先截取十条收费事件或十个成员再求和，否则会改变题目要计算的全体费用。

    After sorting, retain the ten highest-liability root accounts. Limiting charge rows or members before aggregation would compute the wrong population.

聚合函数

SUM · 求和

SUM(numeric_expression)

输入组内数值，返回总和；输入numeric时返回numeric。忽略NULL。

本作业中的作用

输入与输出示例

边界与常见错误

COALESCE · 首个非空值

关键字/查询结构

WITH / CTE · 给中间查询命名

WITH counts AS (SELECT ...) SELECT ... FROM counts;

命名结果仅对当前SQL可见，便于把计算分阶段。不是创建永久表，也不必然物化。

本作业中的作用
Q1把计数与排名分开；Q4给最新事件中间结果命名。
输入与输出示例
教学：WITH x AS (SELECT 2 AS n) SELECT n+1 FROM x; 返回3。
边界与常见错误
多个CTE用逗号隔开；CTE结束后的外层SELECT仍属于同一条语句。优化器可内联，不要用书写结构猜扫描次数。

关键字/集合运算

WITH RECURSIVE / UNION ALL · 逐层扩展

WITH RECURSIVE tree AS (seed UNION ALL recursive_term) SELECT ...;

先运行非递归seed，再反复用上轮结果求下一轮，直到无新行；UNION ALL保留重复。

边界与常见错误
自引用外键不防环。当前向下算法从根出发，孤立环不会被访问；一般递归若无终止/循环检测可能不断扩展。

Q1.3 part 1 materialized view definition 
CREATE MATERIALIZED VIEW MV_ACCOUNT_LIABILITY AS 
WITH RECURSIVE account_tree AS ( 
    SELECT member_id, member_id AS account_id 
    FROM MEMBERS 
    WHERE sponsor_id IS NULL 
 
    UNION ALL 
 
    SELECT child.member_id, parent.account_id 
    FROM MEMBERS child 
    JOIN account_tree parent 
        ON child.sponsor_id = parent.member_id 
) 
SELECT 
    root.member_id, 
    root.member_name, 
    SUM(e.amount) AS total_amount 
FROM account_tree t 
JOIN MEMBERS root 
    ON root.member_id = t.account_id 
JOIN BOOKING_EVENTS e 
    ON e.member_id = t.member_id 
WHERE e.event_type IN ('Return', 'Incident') 
  AND e.event_time >= TIMESTAMP '2026-01-01' 
  AND e.event_time < TIMESTAMP '2026-07-01' 
GROUP BY root.member_id, root.member_name 
ORDER BY total_amount DESC, root.member_id 
LIMIT 10;

从要求推到结论

CREATE MATERIALIZED VIEW ... AS 后复制整个账户责任查询。创建时执行查询并保存当时结果，因此当前保存的是10行冠军账户，不是24000个会员的完整中间映射。

普通视图保存“怎么算”，物化视图还保存“上次算出的行”。教学示例：原查询算得A=100、B=15，物化后保存这两行。后来A增加20，普通视图读出120，物化结果仍是100，直到刷新。
