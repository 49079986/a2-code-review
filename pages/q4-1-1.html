前置知识与数据库背景

一个连接是一个独立服务器会话，用pg_backend_pid辨认。BEGIN到COMMIT/ROLLBACK是一笔事务；未提交写入通常不对其他会话可见。默认READ COMMITTED每条命令取得新快照。行锁协调冲突写入；快照回答可见性，不能代替锁。

06

先读整体，再逐行理解

先pg_backend_pid/current_database确认身份，BEGIN开启事务，SHOW确认read committed。SAVEPOINT collect_attempt只建立可回退点；原文件没有ROLLBACK TO，所以后面错误仍以整个事务ROLLBACK结束。

  1. L1-- Connection 1: keep this connection and its transaction open after this file.

    连接1运行说明：执行本文件后保持同一连接和事务开放，等待连接2完成预订。注释不会自动切换窗口。

    Keep session 1 and its transaction open after the file.

  2. L2\set ECHO all

    psql 元命令 \set ECHO all 将后续输入回显到输出，方便截图核对执行了哪些命令。反斜杠命令由客户端处理，不是服务器 SQL。

    Have psql echo input commands for the experiment record.

  3. L3\pset pager off

    关闭 psql 分页器，让长输出直接显示在当前终端，避免停在分页界面；不改变查询结果或数据库状态。

    Disable the psql output pager.

  4. L4\timing on

    开启 psql 客户端语句计时。它与 EXPLAIN 节点实际时间不是同一统计范围，不能混为同一数值。

    Enable psql statement timing, distinct from plan-node timings.

  5. L5（空行）

    空行用于把相邻语义块分开，帮助区分输入、处理或独立语句；不执行 SQL、不提交事务，也不会重置配置。

    A visual separator only; it executes no statement and changes no transaction or setting.

  6. L6-- Identify the connection used for this experiment.

    注释说明下面记录当前连接身份，为证明两会话独立提供线索；只看两个窗口外观不足以证明两个后台连接。

    Label the session identity query.

  7. L7SELECT pg_backend_pid() AS session_pid,

    pg_backend_pid() 返回当前 PostgreSQL 后台进程的整数 PID，并命名为 session_pid。比较两连接 PID 可核实它们不是同一个会话。

    Return this backend process ID as session_pid.

  8. L8 current_database() AS database_name;

    current_database() 返回当前所连数据库名，命名为 database_name。两会话要在同一个 assignment2 数据库上交错操作；分号结束这条 SELECT。

    Return the current database to check both sessions share assignment2.

  9. L9（空行）

    空行用于把相邻语义块分开，帮助区分输入、处理或独立语句；不执行 SQL、不提交事务，也不会重置配置。

    A visual separator only; it executes no statement and changes no transaction or setting.

  10. L10BEGIN;

    BEGIN 开启连接1的显式事务；这里是 SQL 事务命令，不是 PL/pgSQL 函数体的 BEGIN 代码块。暂不 COMMIT，留待后续题目继续使用。

    Begin session 1 transaction and keep it open.

  11. L11SAVEPOINT collect_attempt;

    SAVEPOINT collect_attempt 在当前事务内设恢复点，不是提交。根脚本没有 ROLLBACK TO collect_attempt，因此后续 Collect 异常仍使事务失败；仅创建保存点不会自动恢复。

    Create a savepoint; the supplied later script never rolls back to it.

  12. L12SHOW transaction_isolation;

    SHOW 读取当前 transaction_isolation，预期需核对为 read committed。它不更改隔离级别；若环境被改过，不能仅凭默认值断言当前设置。

    Display and verify the current transaction isolation level.

  13. L13（空行）

    空行用于把相邻语义块分开，帮助区分输入、处理或独立语句；不执行 SQL、不提交事务，也不会重置配置。

    A visual separator only; it executes no statement and changes no transaction or setting.

  14. L14-- Find each vehicle's latest event before checking whether it is a Return.

    注释强调先确定每辆车的最新事件，再判断 Return；若先筛 Return，就可能忽略更新的 Reserve 而错误判断可用。

    Determine the latest event before testing availability.

  15. L15WITH latest_events AS (

    WITH 定义查询内临时名称 latest_events。括号内为每辆车选一条最新记录，外层再检查实验车。CTE 不是永久表，也不自动锁定车辆。

    Define a query-local latest-events CTE.

  16. L16 SELECT DISTINCT ON (vehicle_id)

    PostgreSQL 的 DISTINCT ON (vehicle_id) 为每个车辆编号保留排序后的第一行。必须结合后面的 ORDER BY 才能明确保留“最新”，不是任意去重。

    Keep the first ordered event per vehicle using PostgreSQL DISTINCT ON.

  17. L17 vehicle_id, event_id, member_id, event_type, event_time

    中间结果保留车辆编号、事件编号、会员、事件类型和时间。event_id 用于同一时间戳下确定顺序，member_id 帮助识别操作人。

    Project the vehicle and event identity, actor, type and time.

  18. L18 FROM BOOKING_EVENTS

    从 BOOKING_EVENTS 事件日志获取历史状态。车辆表没有本题所需的可用布尔字段；本题用最新事件类型定义可用。

    Read the event history used to derive availability.

  19. L19 ORDER BY vehicle_id, event_time DESC, event_id DESC

    先按 vehicle_id 分组排列，再按 event_time DESC、event_id DESC 排最新优先。DISTINCT ON 要求最左排序项与其键匹配；event_id 是时间并列时的稳定规则。

    Order by vehicle, newest time and greatest event ID for ties.

  20. L20)

    关闭 latest_events CTE 的查询体。外层此时看到每辆车最多一条最新事件；这个括号不是事务提交。

    Close the latest-events CTE.

  21. L21SELECT vehicle_id, event_id, member_id, event_type, event_time

    外层输出最新事件的五个字段，供截图展示为何认定该车可用。SELECT 读取本语句快照，不会预留该车。

    Project the latest-event evidence from the CTE.

  22. L22FROM latest_events

    从 latest_events 中间结果读，而不是重新从历史中只找 Return。优化器可内联 CTE，逻辑意义仍是先定最新再判类型。

    Read the latest-event result rather than old Return rows.

  23. L23WHERE vehicle_id = 'VEH-0004'

    将实验对象固定为 VEH-0004，必须在连接2和连接1后续插入中使用同一编号。旧版 Study 用 VEH-0001，其截图不能直接当此版实验结果。

    Use the current script vehicle VEH-0004, distinct from the archived experiment.

  24. L24 AND event_type = 'Return'

    要求该车最新事件是 Return，才把它视为当前可用。AND 与前一条件同时成立；没有输出表示这次快照下没有符合条件的对象。

    Require the already-selected latest event to be Return.

  25. L25ORDER BY vehicle_id

    按车辆编号排序。本查询已经固定单个 vehicle_id，因此最多一行，此排序没有进一步解决 event_time 的并列。

    Order the final candidate by vehicle ID.

  26. L26LIMIT 1;

    最多返回一行并以分号结束可用性检查。LIMIT 1 不会锁行、不保证稍后还可用，也不结束事务。

    Return at most one candidate without locking or committing.

  27. L27（空行）

    空行用于把相邻语义块分开，帮助区分输入、处理或独立语句；不执行 SQL、不提交事务，也不会重置配置。

    A visual separator only; it executes no statement and changes no transaction or setting.

  28. L28-- The availability check is fixed to the vehicle selected in the recorded run.

    注释说明这版代码把查询固定到记录实验中的车辆。可重复运行前需核查其真实最新状态，不能假定固定编号永远可用。

    The vehicle is fixed to this recorded experiment; recheck state on rerun.

  29. L29-- Leave this transaction open.

    保持连接1事务开放，让连接2的修改发生在两次操作之间。普通读取本身没有取得阻止另一会员预订的车辆行锁。

    Leave transaction 1 open for the interleaving.

  30. L30-- Continue with Q4.1 (2) in Connection 2 before returning to Connection 1.

    切到另一个独立会话运行 Q4.1(2)，待其提交成功后再回到本连接继续 Q4.1(3)。不能把两个脚本顺序贴进同一连接冒充并发。

    Run part 2 in a genuinely independent session before returning.

日期时间函数

NOW · 事务起点时间

NOW() → timestamp with time zone

无参数，返回当前事务开始时间，事务内多次调用保持稳定。

本作业中的作用
Q4记录现在的Collect，以及NOW()+INTERVAL '3 days'的Reserve。
输入与输出示例
教学：同一事务等10秒再NOW()仍是事务开始时间；加3 days是三天后的时间值。
边界与常见错误
event_time为timestamp without time zone，赋值时按会话时区转换，不能忽略环境。想读墙钟是另一函数clock_timestamp，原代码未使用。

pg_backend_pid() → integer; current_database() → name

前者返回当前后端进程编号，后者返回当前连接数据库名，均无参数。

关键字/查询结构

WITH / CTE · 给中间查询命名

WITH counts AS (SELECT ...) SELECT ... FROM counts;

命名结果仅对当前SQL可见，便于把计算分阶段。不是创建永久表，也不必然物化。

本作业中的作用
Q1把计数与排名分开；Q4给最新事件中间结果命名。
输入与输出示例
教学：WITH x AS (SELECT 2 AS n) SELECT n+1 FROM x; 返回3。
边界与常见错误
多个CTE用逗号隔开；CTE结束后的外层SELECT仍属于同一条语句。优化器可内联，不要用书写结构猜扫描次数。

关键字

ORDER BY / DESC / LIMIT / AS

ORDER BY collections DESC, station_id ASC LIMIT 1

排序键从左到右比较；默认ASC，DESC降序；LIMIT限制输出；AS给对象/列起名。

本作业中的作用
每类冠军、账户top10、最新事件、同值稳定次序。
输入与输出示例
教学：次数5/ID2与5/ID1，降序次数相同再ID升序，ID1先。
边界与常见错误
LIMIT无确定排序可能不稳定；视图或物化关系调用方需要保证显示顺序时显式ORDER BY。

PostgreSQL查询语法

DISTINCT ON · 每组保留首行

SELECT DISTINCT ON (vehicle_id) ... ORDER BY vehicle_id, event_time DESC, event_id DESC

每个vehicle_id只留排序后的第一行；ORDER BY最左表达式须对应DISTINCT ON。

本作业中的作用
当前根Q4.1.1取每辆车最新事件，外层再筛Return。
输入与输出示例
教学：同车09:00 Return、10:00 Reserve保留10:00 Reserve。
边界与常见错误
先筛Return会回答另一个问题。没有time/ID稳定排序时“第一行”不确定；其他数据库未必支持此扩展。

命令/配置参数

SET / SHOW / enable_* · 会话配置

SET enable_seqscan = off; SHOW transaction_isolation;

SET改变当前连接后续配置，SHOW读取。enable_indexscan/indexonlyscan/bitmapscan/seqscan是不同开关。

本作业中的作用
Q3.2三种设置组最后全部恢复on；Q4 SHOW确认默认隔离。
输入与输出示例
教学：只SET enable_indexscan=off时bitmap仍可能运行，所以索引抑制组需关三种。
边界与常见错误
off通常是抑制而非绝对无法使用；同文件需在同会话运行。配置不是SQL函数，也不修改表数据。

事务控制语句

BEGIN / COMMIT / ROLLBACK / SAVEPOINT

BEGIN; SAVEPOINT s; ... COMMIT; / ROLLBACK TO s;

BEGIN开启事务；COMMIT成功则持久化；ROLLBACK撤销；SAVEPOINT标记局部可恢复点。

本作业中的作用
Q4保持两事务重叠，异常后COMMIT实际返回ROLLBACK。
输入与输出示例
教学：第一UPDATE成功、第二死锁，受害事务第一次更新也被撤销。
边界与常见错误
SAVEPOINT本身不自动恢复；需ROLLBACK TO。函数体BEGIN...END是语言代码块，不是独立事务。
相关题目：Q4.1.1 · Q4.1.3 · Q4.2.1
隔离级别与可见性

READ COMMITTED / snapshot · 读已提交快照

SHOW transaction_isolation;

默认READ COMMITTED每条命令看到该命令快照允许的已提交内容和自身可见修改。

本作业中的作用
T1先见Return，T2提交后T1后续Collect触发器见Reserve。
输入与输出示例
教学：两条SELECT之间别人提交更新，第二条可以读到不同值。
边界与常见错误
事务打开不固定首次快照；快照不是预留锁。普通SELECT仍取得兼容表锁，原题“无锁”是简化。
相关题目：Q4.1.1 · Q4.1.2 · Q4.1.3 · Q4.1.4
触发器与PL/pgSQL

BI_COLLECT / NEW / RAISE EXCEPTION

BEFORE INSERT ... FOR EACH ROW EXECUTE FUNCTION UDF_BI_COLLECT();

每个插入候选行之前调用函数；NEW是拟插入记录；RETURN NEW允许继续，RAISE EXCEPTION拒绝并抛错。

本作业中的作用
Collect时读该车按时间/ID最新事件，检查Incident、Collect或其他会员Reserve。
输入与输出示例

边界与常见错误
