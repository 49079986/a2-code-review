英文原题 · Original task

作业要求 PDF · a2-2026-v1.pdf · Q4.2 Deadlock (3 marks)

In Q4.1 neither transaction could make progress on the other's terms, but only one of them was ever blocked. A deadlock is the symmetric case: two transactions each hold something the other is waiting for, so neither can move. Neither has done anything wrong on its own — it is the interleaving that traps them. Two staff are correcting odometer readings after a service run, and they work through the same two vehicles in opposite orders.

(1) In two psql connections, begin a transaction in each. In your first connection, update the odometer of VEH-0401, and then the odometer of VEH-0501. In your second connection, update those same two vehicles in the opposite order. Run the statements one at a time so you can see which one blocks. Report what happened at each step, quoting any error message in full. (1.5 marks)

Q4.1 中两个事务的业务意图不能同时满足，但只涉及一方受阻。死锁（deadlock）是对称的情况：两事务各持有对方等待的资源，因此双方都不能前进。单独看每个事务都没有做错，陷阱来自执行交错。两名员工维修后修正相同两辆车的里程，操作顺序恰好相反。

前置知识与数据库背景

一个连接是一个独立服务器会话，用pg_backend_pid辨认。BEGIN到COMMIT/ROLLBACK是一笔事务；未提交写入通常不对其他会话可见。默认READ COMMITTED每条命令取得新快照。行锁协调冲突写入；快照回答可见性，不能代替锁。

    按注释标出的顺序在两个独立连接分别运行；文件把两会话放在一起便于阅读，并不自动创建两个会话。

  2. L2-- Do not execute this entire file in a single connection.

    不能把整份脚本一次执行在一个连接中：那样两次 BEGIN 不是两个并发事务，也无法形成相互等待。

    Do not execute the entire script in a single connection.

  3. L3-- The deadlock victim may differ on a rerun.

    死锁受害事务不保证固定为某个连接；当前版本注释记录连接2被回滚，旧版资料可能相反，必须按各自日志说明。

    连接1开始事务并先更新 VEH-0401；它将持有该行锁直到事务结束，给稍后的等待关系提供一条边的资源。

    Session 1 starts and updates vehicle 0401 first.

  12. L12BEGIN;

    开启连接1事务；下一个 UPDATE 获得的行锁会在此事务提交或回滚前保留。

    Begin session 1 transaction.

  13. L13UPDATE VEHICLES

    对 VEHICLES 执行 UPDATE，具体列、增量和目标行分别在下面的 SET/WHERE 指定。UPDATE 不是普通只读查询。

    将原 odometer 加10写回。右侧 odometer 取该行原值，左侧是要改的列；这不是把所有里程统一设成10。

    返回 UPDATE 后的 vehicle_id 和 odometer，便于核对修改是否完成；返回结果仍可能是尚未提交值。

    转到连接2，先锁另一辆 VEH-0501。两个事务以相反顺序持有第一把锁，是形成死锁的重要条件。

    Session 2 starts by updating the other vehicle first.

  19. L19BEGIN;

    开启连接2独立事务；不能在连接1运行本行来冒充第二笔并发事务。

    Begin the independent session 2 transaction.

  20. L20UPDATE VEHICLES

    连接2更新 VEHICLES，下面 WHERE 把它定位到 VEH-0501。此时两事务修改不同车辆，可以各自先成功。

    Start session 2 first update on the other vehicle.

  21. L21SET odometer = odometer + 20

    连接2把目标里程加20，用不同于连接1的增量，方便最终从结果判断哪一事务真正提交。

    Increase the session 2 target odometer by 20.

  22. L22WHERE vehicle_id = 'VEH-0501'

    锁并修改 VEH-0501，连接2持锁直到事务结束；此时连接1持0401、连接2持0501。

    Target vehicle 0501 and retain its row lock in session 2.

  23. L23RETURNING vehicle_id, odometer;

    返回连接2未提交的更新值。客户端能看见返回行，不等于另一事务能看见新值或该修改已经持久保存。

    Return session 2 updated row before commit.

    A visual separator only; it executes no statement and changes no transaction or setting.

  25. L25-- Connection 1: this statement waits for Connection 2.

    连接1尝试第二辆车时应等待连接2释放0501。此刻只有 T1→T2 一条等待边，还没有闭环，因此等待不等于死锁。

    Session 1 waits for session 2; a single wait edge is not a deadlock.

  26. L26UPDATE VEHICLES

    连接1发起第二次 UPDATE；必须留它等待，再到连接2运行下一段，才能让另一边也进入等待。

    Start session 1 second update and leave it waiting.

  27. L27SET odometer = odometer + 10

    连接1准备给0501加10；在获得必要行锁之前不会完成该修改，所以不能把预期增量当作已提交结果。

    Attempt the second +10 update, pending acquisition of the row lock.

  28. L28WHERE vehicle_id = 'VEH-0501'

    目标 VEH-0501 已被连接2修改并持锁，连接1通常等待对方事务结束，形成 T1→T2。

    Wait on vehicle 0501 currently locked by session 2.

  29. L29RETURNING vehicle_id, odometer;

    该 UPDATE 只有恢复并成功后才会返回新行；等待时 psql 没有正常 UPDATE 完成输出，不能再在同一连接同步执行下一命令。

    RETURNING is produced only if this blocked update completes.

  30. L30（空行）

    空行用于把相邻语义块分开，帮助区分输入、处理或独立语句；不执行 SQL、不提交事务，也不会重置配置。

    A visual separator only; it executes no statement and changes no transaction or setting.

  31. L31-- Connection 2: this statement completes the wait-for cycle.

    连接2再尝试0401会等待连接1，产生 T2→T1，与原来的 T1→T2 构成环。DBMS检测后中止一个事务打破环。

    Session 2 second request closes the wait-for cycle.

  32. L32UPDATE VEHICLES

    连接2发起对另一车辆的 UPDATE。死锁来自两个事务交错获取资源，不是这条语句单独语法错误。

    Start session 2 second update that creates the cycle.

  33. L33SET odometer = odometer + 20

    连接2准备再加20。若它成为死锁受害者，这次和它之前对0501的加20都不能提交。

    Attempt another +20; victim rollback also discards its earlier update.

  34. L34WHERE vehicle_id = 'VEH-0401'

    目标0401由连接1持锁，连接2等待连接1事务结束。完整环是 T1等T2的0501、T2等T1的0401。

    Request vehicle 0401 held by session 1 and complete the cycle.

  35. L35RETURNING vehicle_id, odometer;

    请求若因 deadlock detected 被取消，此 UPDATE 不会返回正常更新行。需保存完整 ERROR、DETAIL 和 CONTEXT，而不是只留最后一句。

    The victim update produces an error rather than a successful RETURNING row.

  36. L36（空行）

    空行用于把相邻语义块分开，帮助区分输入、处理或独立语句；不执行 SQL、不提交事务，也不会重置配置。

    A visual separator only; it executes no statement and changes no transaction or setting.

  37. L37-- Connection 2: COMMIT reported ROLLBACK in the recorded run.

    当前根脚本注释记录连接2 COMMIT 输出 ROLLBACK。它与旧版可能选择连接1作受害者的证据必须分开；结论应依该版本完整日志核实。

    This version records session 2 as the victim; do not mix archived outcomes.

  38. L38COMMIT;

    在连接2执行 COMMIT；若已被死锁错误置为失败状态且未恢复保存点，实际结束为 ROLLBACK，先前未提交的加20也被撤销。

    End failed session 2 by rollback and discard its uncommitted +20 changes.

  39. L39（空行）

    空行用于把相邻语义块分开，帮助区分输入、处理或独立语句；不执行 SQL、不提交事务，也不会重置配置。

    A visual separator only; it executes no statement and changes no transaction or setting.

  40. L40-- Connection 1: commit and report the final odometers.

    连接1作为本版记录的幸存者，其等待更新可在对方回滚释放锁后继续；随后提交并检查两车最终里程。

    Commit the surviving session 1 and verify the final readings.

  41. L41COMMIT;

    连接1提交两次成功的加10更新并释放锁。只有这条 COMMIT 成功后，其他会话才应把两次加10视为已提交。

    Commit session 1 two successful +10 updates.

  42. L42SELECT vehicle_id, odometer

    再次查询两车编号及里程，与初始 SELECT 比较。若连接2确实回滚且无其他并发改动，预期每车只增加10；这是条件推导，实测数字看本版证据。

    从车辆表读取已经提交的里程，既不是读取事件日志，也不是读取先前 RETURNING 的缓存。

    仍只核对0401和0501，保持最终结果与初始基准为同一组车辆。

事务控制语句

BEGIN / COMMIT / ROLLBACK / SAVEPOINT

BEGIN; SAVEPOINT s; ... COMMIT; / ROLLBACK TO s;

BEGIN开启事务；COMMIT成功则持久化；ROLLBACK撤销；SAVEPOINT标记局部可恢复点。

本作业中的作用
Q4保持两事务重叠，异常后COMMIT实际返回ROLLBACK。
输入与输出示例
教学：第一UPDATE成功、第二死锁，受害事务第一次更新也被撤销。
边界与常见错误
SAVEPOINT本身不自动恢复；需ROLLBACK TO。函数体BEGIN...END是语言代码块，不是独立事务。
相关题目：Q4.1.1 · Q4.1.3 · Q4.2.1
DML语句

INSERT ... SELECT / VALUES / UPDATE ... RETURNING

INSERT INTO t(cols) SELECT ...; UPDATE ... RETURNING vehicle_id,odometer;

INSERT SELECT把查询结果作为新行；VALUES写字面行；RETURNING输出本语句改变的行字段。

本作业中的作用
Q1.3选最大有赞助会员插入；Q4显示Reserve/里程修改值。
输入与输出示例
教学：149100+10 RETURNING149110，但BEGIN未提交时他人尚不能视为已提交。
边界与常见错误
UPDATE没WHERE可能改全表；RETURNING成功不是COMMIT成功。INSERT列顺序必须与SELECT/VALUES一一对应。

并发概念

Row lock / deadlock / wait-for graph · 行锁、死锁与等待图

T1 → T2 means T1 waits for T2

UPDATE持冲突行锁直到事务结束；等待环使所有参与者无法前进，数据库中止受害事务打破环。

本作业中的作用
T1持0401等0501，T2持0501等0401；本轮T2回滚、T1提交。
输入与输出示例
教学：只有T1→T2是等待；再出现T2→T1才成环。
边界与常见错误

Deadlock explanation 
T1 updates VEH-0401 by 10 and holds its row lock. T2 updates VEH-0501 by 20 and holds 
the other row lock. T1 then requests VEH-0501 and waits. While it is waiting, T2 requests 
VEH-0401, completing the cycle. Both updates cannot finish until the other transaction ends. 
PostgreSQL detects the deadlock and aborts T2 in this recorded run. T2's earlier +20 on 
VEH-0501 is undone and its locks are released. T1's waiting update resumes, returning 
122160, and T1 commits. T2's attempted COMMIT reports ROLLBACK. Final values are 
VEH-0401 = 149110 and VEH-0501 = 122160.

从要求推到结论

初始149100/122150。T1更新0401加10，暂时149110但未提交，持锁；T2更新0501加20，暂时122170但未提交，持锁。T1请求0501等待，这时只有T1→T2，仍不是死锁。

T2再请求0401，T2→T1闭合成环。PostgreSQL检测后中止本轮T2，撤销它先前成功的+20并释放锁；T1等待语句继续，使0501变122160。T2 COMMIT显示ROLLBACK，T1 COMMIT成功，最后149110/122160。

UPDATE RETURNING显示的是当前事务看到的新值，不等于已经提交。原生T1等待116906.993ms包含人切窗口输入命令的等待，不能解释为更新两辆车要算116秒；T2报错1019.158ms也不是普通扫描速度。
