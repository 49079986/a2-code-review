04

前置知识与数据库背景

heap是表的实际行页，B-tree索引是另一套键到记录位置的结构。索引不自动含所有输出列。选择率是匹配行数/输入总行数；页覆盖率是涉及多少数据页，两者不同。BOOKING_EVENTS索引为(event_type,event_time)，MEMBERS表达式索引为规范化域名。

06

先读整体，再逐行理解

默认B-tree键可想成电话簿的“姓、名”：先分event_type，再在相同类型内按event_time排序。教学例：(Incident,3月1日)、(Incident,3月2日)、(Return,3月1日)。要找Incident整个3月可以定位该类型的一段连续时间区间。

  1. L1-- Create a composite index with event_type as the leading column.

    注释提醒复合索引的首列是 event_type；列顺序决定同类型内部再按时间排列，不是两个独立单列索引。

    Source comment: Create a composite index with event_type as the leading column.

  2. L2CREATE INDEX IDX_EVENT_TYPE_TIME

    创建名为 IDX_EVENT_TYPE_TIME 的索引。没有指定 USING 时 PostgreSQL 默认使用 B-tree；创建索引增加一种可选访问路径，不强迫查询使用它。

    Create IDX_EVENT_TYPE_TIME using PostgreSQL’s default B-tree access method. It adds an available path rather than forcing its use.

  3. L3ON BOOKING_EVENTS (event_type, event_time);

    在 BOOKING_EVENTS 上依次索引 event_type、event_time。先固定类型，再限制其内部时间范围很有效；两列不是两份独立单列索引，后续写入也要维护这棵索引。

    Index event_type first and event_time second on BOOKING_EVENTS. Type equality plus an internal time range is effective; this is one composite index, and writes must maintain it.

为什么 (event_time,event_type) 不能当作完全相同的答案？

键排列不同，题目明确要求event_type先。类型等值、时间范围可利用按类型分区后的连续时间段，调换顺序会改变访问特点。

再检查一个关键点

为什么索引不自动让amount可从索引返回？

展开参考答案

它只索引event_type与event_time，没有amount键或INCLUDE列，因此金额仍需heap取得。
